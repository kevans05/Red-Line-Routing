Red-Line-Routing Server

Phase 1 demo: keypair identity, enrollment, challenge/response login, a signed hash-chained event, and real-time broadcast — the foundations the rest of the app builds on.

1. Local identity

Generates an Ed25519 keypair in this browser tab. The private key is stored only in this browser's localStorage and is never sent to the server.

No local identity yet.

2. Enroll this device

Paste an enrollment code (the server prints a bootstrap admin code to its console on first run, or an admin can mint one via POST /admin/users).

3. Log in

Challenge/response: the server hands out a nonce, this device signs it, the server verifies the signature against the enrolled public key and issues a session token.

4. Project + real-time events





Open this page in a second tab, connect both to the same project id, then send an event from one tab — it should appear in the other tab's log instantly.

5. Drawings registry

Adding a drawing posts a signed registry_add event through the same pipe as section 4 — the server replays it onto the drawings table, and any connected tab sees it live.
